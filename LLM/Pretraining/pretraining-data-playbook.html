Pretraining Data Curation Playbook

Complete Reference Guide — Based on FineWeb (HuggingFace)

Note-Taking Framework (Use For Any Paper/Article)

Every section you study should go through these 6 steps:

  1. Translate — Rephrase in plain English. Strip jargon. If you can say it differently, you understood it. If you can't, you didn't.
  2. Filter — Split into three buckets: must remember (concepts, insights, formulas), nice to know (specific numbers, names), and skip (implementation details, tool names, citations).
  3. Connect — Link to something you already know. Connections turn isolated facts into a web that's harder to forget.
  4. Visualize — What doodle would make this click? If you can't draw it, you probably don't understand it well enough.
  5. Interview Flip — If an interviewer asked about this, what's the one sentence that sounds smart? Extract the "so what."
  6. Anti-note — What should you NOT write? If everything goes in your notes, nothing stands out.
The rule: If your notes look exactly like the source, you wasted your time. Good notes are shorter, simpler, and in your voice.

1. Where Does Training Data Come From?

Two options:

Option 1: Crawl it yourself — OpenAI, Anthropic do this with their own crawlers.

Option 2: Use public crawl data — CommonCrawl (non-profit, crawling since 2007).

CommonCrawl Key Numbers

One crawl (April 2024) = 2.7 billion web pages = 386 TiB of HTML

96 crawls released since 2013. New crawl every 1–2 months.

LLMs aren't trained on curated data — they start with massive, messy web crawls. The real work is in cleaning it up.

2. What Is "High Quality" Data?

High quality is not well defined in pretraining. Even humans can't always agree. Quality depends on what you're training the model for, not on the text itself.

Three Methods to Judge Data Quality

MethodHowSpeedCostReliability
Perplexity (Wikipedia)Train on Wikipedia, score new dataFastCheapLow
Small model + evalsTrain small models, evaluate on diverse benchmarksMediumMediumMedium
Human evaluationHumans rank outputs (e.g., LMSYS Arena)SlowExpensiveHigh
Perplexity flaw: Biases toward formal/encyclopedic text, filters out useful informal content.
Small model warning: Don't overfit to one benchmark — pick diverse evals.
Human eval problem: Requires instruction finetuning first, adding noise.
There's no perfect way to evaluate data quality — each method trades off cost vs reliability.

3. Ablation Methodology

Ablation = remove one step and compare results. Change only ONE thing, keep everything else identical, measure the difference.

Train two identical models (same size, architecture, tokens, one epoch). Only difference = the training data. Compare eval scores. If scores improve → the step helped.

Ablation Model Setup

1.82B parameters, Llama architecture, GPT2 tokenizer. Trained on ~28B tokens (Chinchilla optimal for this model size).

Chinchilla Optimal: DeepMind (2022) — for a given compute budget, optimal ratio is ~20 tokens per parameter. Before: huge models, too little data. After: scale data proportionally.

How to Pick Good Eval Benchmarks (3 Criteria)

1. Low variance — stable signal across data resamplings

2. Monotonically increasing — score goes up as training progresses

3. Above random — meaningfully above chance

Key benchmarks: MMLU (57 subjects) and HellaSwag (commonsense) come up most in interviews.

4. Text Extraction

CommonCrawl has two formats:

WARC = raw HTML + metadata (the full thing)

WET = text already extracted by CommonCrawl (lower quality)

FineWeb used WARC + trafilatura library for better extraction.

Experiment Results

More data ≠ better data. Starting from raw HTML gives you more control over quality.

5. Base Filtering

Three-step filtering (following RefinedWeb):

1. URL blocklist → remove adult content

2. Language filter → fastText classifier, English only (score ≥ 0.65)

3. Quality + repetition filters → from MassiveText (removes gibberish, repeated text)

Raw CommonCrawl → after base filtering = ~36 trillion tokens

Every major LLM dataset follows this same structure: remove harmful → filter language → remove low quality/repetitive. The specifics differ but the pipeline is universal.

6. Deduplication

Why Deduplicate?

The web has mirrors, aggregators, templated pages, and crawler artifacts. Removing duplicates: improves model performance, reduces memorization (better generalization), and increases training efficiency (same compute, more diverse data).

Two Approaches

Exact dedup — identical matches

Fuzzy dedup — similarity-based (close enough)

MinHash (What FineWeb Used)

Break documents into 5-grams. Compute 112 hash functions. Split into 14 buckets × 8 hashes. If two docs share all 8 hashes in ANY bucket → duplicate. Target: ≥ 75% similar.

7. The Deduplication Trap

Assumption: More dedup = always better. WRONG.

What They Tried (Cross-Dump Dedup)

Dedup ALL 90+ dumps together chronologically. Oldest dumps lost >90% of data. Result: 36T → 4T tokens.

Surprise: Model showed almost no improvement over non-deduped data.

The Deep Dive (Dump 2013-48)

The 10% "kept" data was actually WORSE than the 90% removed data. Kept data = ads, keyword spam, bad formatting.

Key Insight: Uniqueness ≠ Quality
Good content gets duplicated across the web (popular articles, Wikipedia mirrors). Garbage is often unique (random spam). Cross-dump dedup kept unique garbage and removed common good content.

The Fix: Individual Dump Dedup

Dedup each dump independently. Result: 20T tokens. Performance: matched RefinedWeb.

Aggressive deduplication can backfire because high-quality content tends to be replicated across the web, while low-quality spam is often unique.

8. Learning From C4's Filters

C4 (2019, ~175B tokens) — still competitive despite age. Used in Llama1.

Key Finding

Terminal punctuation filter = biggest individual boost BUT removes 30% of data (too destructive).

All other filters combined = better performance, only ~7% removed.

Decision: Use all C4 filters EXCEPT terminal punctuation.

The most aggressive filter isn't always the best. C4 from 2019 is still competitive in 2024, proving filtering quality matters more than data freshness.

9. Systematic Filter Development

4-Step Process

1. Compute 50+ metrics on high-quality vs low-quality data

2. Find metrics with biggest distribution gap (Wasserstein distance)

3. Pick threshold from histogram inspection

4. Validate with ablation runs

3 Winning Filters

FilterThresholdData Removed
Lines ending with punctuation≤ 0.12 → remove10%
Duplicate line characters≥ 0.1 → remove12.5%
Short lines (<30 chars)≥ 0.67 → remove3.7%

All three combined: ~22% removed → surpassed C4 performance.

This 4-step framework is reusable for any data quality problem, not just LLMs. Surgical filtering beats aggressive filtering.

10. Final FineWeb Pipeline

The complete pipeline, in order:

1. Text extraction (WARC + trafilatura)

2. Base filtering (URL blocklist, language, quality/repetition)

3. Independent MinHash dedup per dump

4. C4 filters (except terminal punctuation)

5. Custom filters (punctuation ratio, duplicate lines, short lines)

Result: 15T tokens → best performing open web dataset

11. FineWeb-Edu — The Educational Quality Layer

How They Built It (3 Steps)

1. LLM-as-annotator: Used Llama-3-70B to score 500K samples on educational quality (0–5 scale)

2. Train cheap classifier: Snowflake-arctic-embed + regression head, F1 = 82% at threshold 3

3. Filter at scale: Run classifier on all 15T tokens → keep only score ≥ 3

Result: 92% removed → 1.3T tokens remain → outperforms everything

The Pattern: LLM Distillation for Data Curation

LLM annotates small sample (expensive but feasible) → Train tiny classifier on annotations (cheap) → Run classifier on everything (fast). Used by Llama 3 and Phi-3. State-of-the-art approach.

Threshold Tradeoffs

Higher threshold (4–5) → better on MMLU, ARC but worse on HellaSwag/PIQA

Threshold 3 = best balance. Also released threshold 2 version: 5.4T tokens.

They removed 92% of data and performance went UP. Quality >>> Quantity.

12. Synthetic Data & CommonCrawl Over Time

Not all crawls are equal — some perform much better, no conclusive explanation.

Synthetic Data Contamination

Proxy detection: Frequency of ChatGPT-isms ("delve", "rich tapestry", "it's important to note", "certainly!", "dive into")

Flat until 2023-14 → steep increase after ChatGPT release (late 2022).

At small scale: doesn't seem to hurt (might help). At large scale: unknown.

Model Collapse concern: Training on AI-generated data could degrade future models. Active area of research.

Recurring Principles

  1. Quality >>> Quantity — More data can hurt. 92% removal improved performance.
  2. Uniqueness ≠ Quality — Good content is duplicated because it's good. Garbage is often unique.
  3. Surgical filtering > Aggressive filtering — Smart 10% removal beat blunt 30% removal.
  4. Validate every step — Ablation test each pipeline decision. Don't assume.
  5. Small-scale ≠ Large-scale — 28B token results don't always hold at 350B+.
  6. Data engineering is about balance — Every technique has diminishing returns and side effects.
  7. LLM distillation for data curation — Expensive LLM → cheap classifier → scale. State of the art.
